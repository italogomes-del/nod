# ADA-232 · Fim de trabalho com saída obrigatória e "volto quando…" no card

Plano de engenharia (Xumbrega, 2026-11-07). Tarefa ADA-232 do quadro do Marlon. Relacionadas: ADA-228 (PR #677 parou
5x em 05/11), ADA-230 (frente aberta pela tarefa aparece como parada), ADA-23, ADA-16, ADA-28. Referência: wakeups de
issue do Multica (`--until-pr checks`, `--max-fires`, pausa por laço/rajada, `wakeup trigger`).

**Meta:** nenhum trabalho de tarefa acaba em silêncio. Todo turno de tarefa termina numa de 4 saídas, e o card diz numa
linha só o que está acontecendo e por quê.

**Já decidido (não reabrir):** sem painel, coluna ou estado novo. Sua vez continua sendo o único lugar de decisão. A
linha do card é discreta: lê como mensagem, não como alerta.

Lentes aplicadas: revisão de engenharia (`/plan-eng-review`: arquitetura, dados, concorrência, testes, desempenho), de
design (`/plan-design-review`, seção 9) e a regra de paridade (`/acao-no-chat`, seção Ações).

## 1. Arquitetura

```
 turno da tarefa assenta (assentar-turno)
        │  ferramentasChamadas do turno
        ▼
 saidaDoTurno(chamadas, tarefa antes/depois)  ── domínio puro ──►  andou | voce | bloqueado | volta | nenhuma
        │  grava quadro_execucoes.saida (+ volta_motivo / volta_em)
        ▼
 cuidarDaTarefa (varredor)
        │
        ▼
 decidirAposTermino  ──► concluido + saida=nenhuma
        │                   ├─ 1ª seguida  → reacionar_sem_saida  (retomada na MESMA cadeia/sessão, com o aviso)
        │                   └─ 2ª seguida  → precisa_de_voce "o bot parou 2x sem saída"
        ├─► saida=volta     → nada agora; a volta (despertar/espera/ci) retoma a cadeia
        └─► falhou          → igual hoje (repetir / bloquear)

 volta "quando a CI terminar":  turno de retomada pendente, acordar_quando='ci', acordar_em = agora+24h
        varredor a cada passe: checks do PR terminados? → acordar_em = now() (mesma cadeia/sessão)
        passou das 24h → o reivindicar entrega sozinho, com "a CI não terminou em 24h"

 freios (antes de qualquer reacionamento):
   mesma volta 3x sem novidade → pausa (alarmeDeVoltas, já existe)
   acionamentos da tarefa na hora ≥ 12 → Precisa de você (agora conta retomadas e novas tentativas)
   ir-e-voltar entre colunas → frearDepois (igual hoje)

 card:  montarQuadro → estadoLinha {tipo, motivo?, voltaEm?}  →  1 linha discreta
```

A regra mora no domínio (`decidirAposTermino`, `saidaDoTurno`), não no prompt: o prompt explica, o motor garante.

## 3. Dados e migrações

Uma migração (próximo número livre na hora de implementar; hoje main está em 0151 e PRs abertos usam 0152 → provável
**0153**, conferir antes do merge):

```sql
SET LOCAL lock_timeout = '5s';
ALTER TABLE quadro_execucoes
  ADD COLUMN IF NOT EXISTS saida text CHECK (saida IN ('andou','voce','bloqueado','volta','nenhuma')),
  ADD COLUMN IF NOT EXISTS saida_em timestamptz;
-- null = turno ainda vivo ou dado anterior (nunca reaciona).

-- A volta já é um turno pendente com acordar_em (0065, ADR-086). A condição 'ci' só anota no turno de retomada o PR a
-- vigiar; acordar_em vira o prazo máximo (24h) e o varredor o traz para now() quando os checks terminam.
ALTER TABLE turnos
  ADD COLUMN IF NOT EXISTS acordar_quando text CHECK (acordar_quando IN ('ci')),
  ADD COLUMN IF NOT EXISTS acordar_pr_url text;
CREATE INDEX IF NOT EXISTS turnos_acordar_ci_idx ON turnos (acordar_em)
  WHERE estado = 'pendente' AND acordar_quando = 'ci';

ALTER TABLE trabalhos ADD COLUMN IF NOT EXISTS tarefa_id uuid REFERENCES quadro_tarefas(id) ON DELETE SET NULL;
```

Vínculo frente→tarefa: ver 3.1. O índice em `turnos` é criado com `CONCURRENTLY` numa migração à parte se o diário exigir (tabela grande).
Sem backfill: execuções antigas ficam `saida=null` e não reacionam. Migração só aditiva, reversível com `drop column`.

### 3.1 Frente aberta pela tarefa (absorve ADA-230)

`trabalhos` ganha `tarefa_id uuid null references quadro_tarefas(id) on delete set null`, preenchido quando um turno de
tarefa abre frente. `estadoDaLinha` considera "trabalhando" se houver frente viva com essa tarefa. Se a ADA-23 já tiver
definido outro modelo para o vínculo quando formos implementar, usamos o dela (suposição S4).

## 4. APIs e ferramentas

- `gerir_quadro` op nova: `{tipo:"acordar_trabalho", tarefa}` → acorda a volta pendente agora (mesma cadeia). Sem volta
  pendente: erro claro "a tarefa não está esperando".
- `POST /api/agentes/:id/quadro/tarefas/:tid/acordar` → mesmo executor.
- `me_chame_as` aceita `quando: "ci"` (exige PR na tarefa) além da hora; o `motivo` vira o texto do card.
- `TarefaDto.estadoLinha` no `GET` do quadro (calculado no servidor, uma vez por `montarQuadro`).
- `ExecucaoDto.saida` e `ExecucaoDto.volta` no detalhe.

## 5. Bordas e erros

| Caso | Comportamento |
| --- | --- |
| Turno conclui sem saída, 1ª vez | Reaciona na hora, mesma sessão, com `AVISO_SEM_SAIDA` ("você parou sem dizer o porquê, escolha uma saída"). |
| 2ª seguida sem saída | Precisa de você, motivo "o bot parou 2x sem saída". Não reaciona mais. |
| Turno falha (plataforma) | Igual hoje (repetir/bloquear). Falha não conta como "sem saída". |
| Pessoa move/cancela a tarefa durante o reacionamento | `andando=false` → nada; o turno em fila é cancelado como hoje. |
| Recado da pessoa chega | Recado vence o reacionamento (`entregar_recado` antes). Zera a conta de sem saída. |
| Volta 'ci' e o PR não tem checks | Acorda no próximo passe ("o PR não tem CI"). |
| Volta 'ci' e a CI não termina | Acorda no `expira_em` (padrão 24h = `ACORDAR_MAX_MINUTOS`) com o motivo. |
| GitHub fora/sem token | Não acorda por erro; tenta no próximo passe; no `expira_em` acorda. Log com o erro, sem token. |
| Mesma volta 3x sem novidade | `alarmeDeVoltas` já pausa e pergunta à pessoa. Mantido. |
| > 12 acionamentos/hora da tarefa | Precisa de você com o motivo de laço do freio. |
| Acordar agora sem volta pendente / em corrida com o varredor | Op idempotente: `update turnos set acordar_em=now() where id=$1 and estado='pendente' and acordar_em>now() returning`; quem perde a corrida recebe "já acordou". |
| Saída marcada e turno depois falha | Vale a última: `saida` é regravada quando a cadeia assenta de novo. |
| Turno do zelador (sem execução) | Não passa por `decidirAposTermino`; continua como hoje. |
| Trabalho de comentário | Não conta nem zera a conta (mesma regra de `tentativasAutomaticasSeguidas`). |

## 7. Desempenho

- `saidaDoTurno` usa as `ferramentasChamadas` já em memória no assentamento: zero consulta extra.
- Volta 'ci': uma chamada de checks por PR esperando por passe do varredor, com índice parcial. Teto natural: tarefas
  esperando CI são poucas; mesmo assim, agrupar por PR e pular PR consultado há < 30 s (igual ao Multica).
- `estadoLinha`: calculado junto de `execucaoDoTurno` em `montarQuadro`, com os dados que ele já carrega + 1 consulta em
  lote às voltas pendentes do quadro (não N+1).

## 8. Riscos e modos de falha

| Risco | Mitigação |
| --- | --- |
| Reacionamento vira laço caro | Máx. 1 por série + teto/hora 12 + `alarmeDeVoltas`. Testado. |
| Falso "sem saída" (bot andou por outro caminho, ex.: moveu pela tela em paralelo) | `saidaDoTurno` também olha a tarefa antes/depois (status, `pr_url`): mudou = andou. |
| Turno longo que legitimamente "só respondeu" (tarefa de pergunta) | Responder na conversa da tarefa e terminar é `terminei`; o prompt diz isso. |
| GitHub rate limit na volta 'ci' | Pular PR consultado há < 30 s; expira acorda de qualquer jeito. |
| Turnos antigos (`saida=null`) reacionando no deploy | `null` nunca reaciona. |
| Migração colide com outro PR | Número escolhido no fim, antes do merge. |
| Zelador e motor acordando a mesma tarefa | Zelador pula tarefa com volta/trabalho vivo. |

Falhas silenciosas: nenhuma planejada — toda decisão nova grava `quadro_execucoes.motivo` ou move para Precisa de você.

## 9. Design (lente `/plan-design-review`)

Protótipo do Gil ainda não existe (suposição S1); o plano usa só peças que já estão no sistema visual.

- **Card, uma linha, `.qd-estado`** (11.5px, `--ink-3`), sem ícone, sem cor de alerta. Texto:
  - `trabalhando` (selo atual `seloTrabalhando`, também com frente viva);
  - `esperando · volta quando a CI terminar` / `esperando · volta às 15h` (reusa `quandoVolta`);
  - `precisa de você` e `bloqueado` (já vêm da coluna; a linha só confirma, cor `--ink-2`, sem vermelho).
  - Nada some do card a não ser o vazio de hoje. "falhou" segue como hoje (é estado de execução real).
- **Detalhe, seção Execuções**: nota na linha do trabalho (`.qd-trab-nota`), como "Nova tentativa sozinha às HH:MM":
  `Volto quando a CI do #677 terminar · Acordar agora` (`.qd-link`, mesmo padrão de Cancelar/Repetir).
- **Hierarquia**: o título da tarefa continua o mais forte; a linha de estado é a mais fraca do card.
- **Mobile**: a mesma frase em `linha()`, truncada com reticências; o motivo inteiro no detalhe.
- **Acessibilidade**: a linha é texto (lido por leitor de tela); "Acordar agora" é `<button>` com rótulo "Acordar o
  trabalho agora".
- **Microcopy**: primeira pessoa do bot no detalhe ("Volto quando…"), terceira no card ("volta quando…"), como já é em
  `web/lib/trabalhos.ts`.
- Nenhum painel, coluna ou estado novo. Sua vez continua sendo o lugar de decisão (Precisa de você).

## Ações

Uma ação nova, nascida `vivo`:

- **`quadro.acordar_trabalho`** — "Acordar agora": dispara já a volta pendente da tarefa, na mesma cadeia/sessão.
  - registro: `src/domain/acoes/quadro.ts` (risco `muda`, `vivo`, via `gerir_quadro`, contrato `tests/integration/paridade-quadro.test.ts`)

  - cartão: nenhum (efeito interno e reversível; não passa por aprovação, igual ao Repetir)

pela tela.

## 12. Suposições para a Ada/Gil confirmarem

- **S1 (Gil):** sem protótipo, o card usa `.qd-estado` numa linha e o detalhe usa `.qd-trab-nota` + `.qd-link`, sem cor de alerta.
- **S2 (Ada):** "esperando a CI" é detectado pelo PR já ligado à tarefa (`pr_url`, gravado na volta em `turnos.acordar_pr_url`); sem PR ligado, `quando:"ci"` é recusado (`sem_pr`) com o caminho: pôr o PR na tarefa (`mudar_tarefa pr_url`) ou usar `esperar_comando` com `gh pr checks --watch`. O estado da CI vem do laço de PRs do quadro (sem chamada nova ao GitHub); PR sem checks acorda depois de 10 min.
- **S3 (Ada):** teto de 12 execuções por tarefa por hora (o `LIMITE_ACIONAMENTOS_HORA` atual), contando retomadas.
- **S4 (Ada):** vínculo frente→tarefa por `trabalhos.tarefa_id`; se a ADA-23 definir outro modelo, seguimos o dela.
- **S5 (Ada):** o zelador continua cobrando prazo vencido; só para de cobrar tarefa com volta marcada (hora, CI ou comando de fundo); o trabalho vivo sem volta segue a regra antiga (turno da tarefa na fila não abre outro).
