Como esta lista foi feita

O OpenMausBot foi clonado no commit 6dd4403 (release v0.1.95, 3 out 2026). Foram lidos o README, as docs (docs/ e o site em apps/docs), o catálogo de strings da interface (src/locales/en.json, 3.491 chaves), as rotas de server/index.ts (cerca de 230 endpoints), electron/, ios/, android/ e as notas das releases v0.1.85 a v0.1.95.

O Nod foi lido no origin/main (1921093), mais as três PRs abertas. O main local estava 53 commits atrás. Os documentos docs/comparacao-openmausbot.md e a seção “O que NÃO existe” do README estão desatualizados (ainda dizem que não há Electron, computador por bot nem Codex) e não foram usados como fonte.

  • Não existe: nada no código nem nos planos.
  • Parcial: existe com limites claros, descritos na linha “No Nod hoje”.
  • Em PR aberta: só numa PR ainda não mergeada.
  • Contraria uma decisão: há ADR ou registro dizendo para não construir. Implementar exige reverter a decisão.
  • A verificar: o levantamento não confirmou nem descartou. Vale uma olhada antes de decidir.
  • Ideia de engenharia: técnica de implementação do OpenMausBot que vale copiar; não é feature visível.

A sugestão de cada item é minha e leva em conta as regras do Nod: minimalismo, a pessoa sempre sabendo o próximo passo, decisões auditáveis, e o Nod sem IA própria rodando no executor do Mac. Esforço: P (dias), M (uma a duas semanas), G (mais que isso).

Nenhum dos dois tem kanban. O “Delegation Task Board” do OpenMausBot está planejado e não foi entregue. O pilar de kanban do Nod é uma chance de chegar antes.
